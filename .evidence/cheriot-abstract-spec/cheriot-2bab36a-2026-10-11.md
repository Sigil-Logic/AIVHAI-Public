**Why `saw` and not `guru`.**  The case, the hand-off note, and `docs/containers.md` named the `guru` switch for this development.  That switch holds `rocq-core` 9.1.0 and no standard library (Guru's stdlib is a sibling checkout the CI script pins in, not an opam package), and every file of `cheriot-abstract-spec` begins with `From Stdlib Require Import ...`, so on `guru` the build stops at `src/Tactics.v`, line 17: "Cannot find a physical path bound to logical path String with prefix Stdlib".  The `saw` switch carries the same Rocq 9.1.0 with `rocq-stdlib` 9.0.0 and builds it.  Found on 2026-10-09; the case and the note now name `saw`.

## What was run

The case's `rerun` commands, with the switch corrected, as rootless podman on the FM host runs them.  Each command's output goes straight to its log, with no pipe in between, and the shell's `$?` after it, podman's exit status, goes to the metadata file.  `$IMG` is the digest above; `--userns=keep-id --user "$(id -u):$(id -g)"` is what rootless podman needs to write into a bind mount of a mode-0700 home directory, and `:Z` is the SELinux label.  With Docker, `docker run --rm -v "$PWD":/work -w /work "$IMG" ...` is the same command.

```bash
RUN=(podman run --rm --userns=keep-id --user "$(id -u):$(id -g)" -v "$PWD":/work:Z -w /work "$IMG")
# E3: the build log
"${RUN[@]}" bash -lc 'eval "$(opam env --switch=saw --set-switch)" && make' > cheriot-2bab36a-build.log 2>&1; echo "E3 exit=$?" >> cheriot-2bab36a-meta.txt
# E2: Print Assumptions in the tree E3 left; the query is echoed into the log ahead of Rocq's answer
"${RUN[@]}" bash -lc 'eval "$(opam env --switch=saw --set-switch)" && make >/dev/null && printf "From cheriot Require Import Properties.\nPrint Assumptions ThreadIsolatedMonotonicity.ThreadIsolatedMonotonicity.\n" > /tmp/pa.v && cat /tmp/pa.v && rocq compile -Q src cheriot /tmp/pa.v' > cheriot-2bab36a-print-assumptions.log 2>&1; echo "E2 exit=$?" >> cheriot-2bab36a-meta.txt
```

## Verdict

**At `2bab36a`, the development builds under Rocq 9.1.0 in the `aivhai-provers` image, and `ThreadIsolatedMonotonicity` is closed under the global context.**  Both evidence nodes of the CHERIoT case can be recorded; neither is pending.  The `FuncNormal` fix is in this commit, the proof script is otherwise unchanged from `f754796` (the diff is that one line of `Spec.v` and comment-only commits), and the theorem checks at this commit.  That rebuts the case's defeater D1, the mis-statement of the hypothesis.  It does not answer the defeater's other half, whether any instruction satisfies `WfNormalInst` as now stated; the case carries that as the open defeater D2.

What this does not show: that any instruction satisfies the corrected `WfNormalInst`.  That is D2's non-vacuity witness, separate follow-up work.
